# Changelog

## Unreleased

### Added

- **Traffic is now recorded persistently (90 days), per day, per session and per project — and the modal has a 流量 tab to show it** (live request 2026-10-14: "目前流量是重启后丢失，增加改为持久记录，最长 90 天" + "按会话/项目记录流量，modal 增加一个 tab 页面"). The in-process tracker answered "which exit served this and how fast" for one host lifetime; `UsageStore` (`src/pool/usage-store.ts`) now answers "what did I spend" across restarts, as one JSON document at `~/.opencode2dsh/usage.json` with four breakdowns: `totals` (all-time, **never trimmed** — the footer's overview figure has to stay honest past the retention window), `days` (one bucket per LOCAL calendar day, kept 90 days), `sessions` (keyed by the host's session id, carrying a readable label — the conversation's first user turn, truncated to 64 chars — capped at 500 by last activity) and `exits` (keyed by exit id, capped at 200; slot-stable ports mean a node keeps its bucket across restarts). Writes are debounced (10s) and atomic (temp file + rename): a response is a few hundred bytes of accounting and rewriting the document per token would be absurd, so a crash costs at most the last window; a corrupt document starts fresh instead of failing every request, and the bad file is left alone for inspection. The write path is single: `attributeUsage()` writes "the active recorder", and `apply()` swaps in the ledger with `setUsageRecorder(usageStore)` — that seam exists so `usage.ts` never imports the ledger (the two would form an import cycle, and the ledger drags `node:fs` along); the ledger's own `record()` updates the run-scope tracker and the persisted buckets in the same call, so both scopes always come from one event. **Sessions**: the adapter now stamps `RoutingContext.usageSession`/`usageLabel` from the HOST's `GenerateOptions.sessionId` (falling back to its own digest id) plus a truncated first user turn — deliberately separate fields from the routing stickiness `session`, which is untouched so routing behaviour cannot change. **Projects** are a READ-time join, not a recorded fact: the LLM request carries no workspace (DSH's own prompt states the cwd is not inferable), so the bridge resolves each session id through `ctx.inject(['workspaceRegistry'])` — `list()` exposes every workspace's `sessionIds` — and a composition without that service reports no project rather than inventing one.
- **The modal has two tabs, and the usage scope is a switch on the settings card** (live request 2026-10-14: "左下角显示总览。插件配置页面可以切换为本次重启的用量统计"). The exit-stats modal's tab bar splits 出口 (the per-exit table, unchanged) from 流量 (the new `UsagePanel`): a scope chip plus requests/tokens/tok-s/sessions/active-days, a 每天 bar list for the last 14 days (bars normalised to the heaviest day in the window, real numbers in the value column), a Top 会话 table (label, project, requests, tokens, last used — the label is what makes a row readable, the full id rides the tooltip) and a project roll-up, with a footnote naming the ledger's size and retention. The scope switch itself lives on the settings card (`ipPool.usageScope`, default `total`, a new 用量统计 section) and is written **immediately** rather than as a form draft — it is a view switch, not a configuration edit, and requiring 保存 to re-read the numbers it governs would be a strange two-step; it governs the exit table's per-exit numbers and the 流量 tab. The **footer entry stays pinned to 总览** (the ledger's all-time totals), because "what have I spent" must mean the same thing regardless of what the modal was last left on. The card's `/status` poll is no longer gated on the pool being enabled: the ledger keeps recording with the pool off (every request lands in the 本机 bucket), and the 用量统计 section needs it either way. A host from before the ledger serves `usage: null` and the client says so instead of showing an empty chart.
- **The exit tables gained row actions: 固定 (pin) and 轮换 (rotate), and the 本机 row can be pinned too** (live request 2026-10-14). The exit-stats modal's last column now carries **icon** buttons — a padlock (固定/取消固定) and a circular arrow (轮换) — per exit row, and the 本机 row carries the padlock as well — pinning it means "every request egresses from this machine", which the operator asked for explicitly ("包括本机也增加此类设置"). All three are one new loopback route, `POST /api/opencode2dsh/ip-pool/exit`, because the modal is mounted on the sidebar footer and therefore has **no settings form** to mutate through: `pin` writes `pinnedExitId` into this plugin's own namespace from the host side (`ctx.settings.mutate('opencode2dsh', [{op:'set', path:['ipPool','pinnedExitId'], value}])` — the same field-name-prefixed path the settings card writes, with an empty value spelled as `unset` so the schema default applies instead of a stored empty string) and pins the live pool in the same request; a read-only profile still pins live and answers `persisted: false`, which the modal renders as 「已生效，但未写入配置（重启后失效）」 rather than pretending the click did nothing. The 本机 button sends `pin-local` and the **host** owns the sentinel, so the browser bundle never spells it and cannot drift from it. `rotate` is the operator's "rotate this exit out": it hands the row to the subscription layer's candidate list, which promotes the next-fastest reserve (`promoted: true` → 「已轮换：候补已补位」) or — when the reserve is exhausted — keeps the exit and sinks it to the pool tail (`promoted: false` → 「已轮换：暂无候补，已移到列表末尾」), with `demoteToTail()` as the fallback when no onboarding round has run in this process — and with a third outcome for the window where a running onboarding/trim holds the rebuild mutex: `replaceExit()` then answers false **without consulting the reserve**, so the route replies `busy: true`, leaves the row untouched and the modal says 「轮换进行中，请稍后重试」 rather than sinking an exit that had a reserve all along; removing the currently pinned exit unpins first, because the pin lives in the settings and a later commit would otherwise re-pin a row that is no longer in the pool — and re-admit it as a **manual** row, since a subscription id like `127.0.0.1:30001` parses as a manual address. The settings card's exit list gets the same icon pair (it keeps its 探测 text button), so both surfaces behave alike. Covered by `test/ip-pool-settings.test.ts` (8 tests: persist+live, `pin-local`, read-only degradation, promote, sink, no-onboarder, unpin-before-remove, refusals) and an apply-level test that the route is mounted and lands the write in the right namespace and path.
- **Pinning to 本机 is a first-class pin: the `local` sentinel** (live request 2026-10-14). `pinnedExitId: 'local'` (the `LOCAL_EXIT_ID` usage bucket) now means "no exit at all": `ExitPool.pinLocal()` stores the sentinel and clears every row's `pinned` flag, and `pick()` answers the sentinel with **null** — the dispatcher's documented direct path — *before* the rotation, because falling through to the pool would silently ignore the operator's click. It cannot collide with a real exit id (those are `host:port` or `scheme://host:port`), and `syncManualExits()` recognises it before the manual-address path, since `parseManualProxy('local')` rejects it and the pin would degrade to "nothing pinned". The status view reports it as `pinned.local`, so the card shows 「固定本机（直连）」 instead of a bare 「固定主力」 badge and the modal can render 取消固定 on the local row. Covered by two pool tests (no-exit selection, sentinel survives a stale-flag sweep), a `syncManualExits` round-trip test and a status-view test.
- **The exit-stats modal has a 地区 column** (live request 2026-10-14): the country/region code for each exit, right after the IP. The code comes from `exitLocation`'s first token, which IS the ISO alpha-2 country code ip-api returns (`admission.ts` builds `` `${countryCode} ${city}` ``), widened to the labels the operator asked for — their two anchors are honoured exactly (香港 → `HK`, 新加坡 → `SGP`), Greater China stays two-letter (`HK`/`TW`/`MO`), the rest use alpha-3 (`JPN`/`KOR`/`USA`/`DEU`/`FRA`/`IND`…), and an unmapped country falls back to its own alpha-2 code rather than a blank so a new airport location is readable the day it appears; a location with no country code at all (a bare city, or an unprobed exit) renders the table's `—` placeholder instead of inventing a region. The full string is still one hover away on the IP cell. The mapping lives in `src/client/region.ts` with `test/region.test.ts` (4 tests, including every location shape measured on the live pool).
- **The 本机 row reads 直连 with a green dot, and the footer button carries the pool's tok/s** (live request 2026-10-14). The local row's status was a grey dot plus 「未走出口」, which read as a fault rather than a working egress — this machine IS an egress, so it now uses the same green dot as a usable exit and says 「直连」. The sidebar footer entry's subline gains the pool-wide output speed (`请求 · token · N tok/s`, the same weighted mean the modal's summary chip shows), hidden at 0 because "0 tok/s" reads as a stall rather than an empty counter; the squeezed/rail variant keeps the token count alone (that is what fits) and carries the speed in its tooltip.

### Changed

- **The stats modal keeps one fixed size across its two tabs** (live request 2026-10-14: "切换 tab 保持窗口大小不变"). Its height was content-driven, so switching between the exit table and the traffic breakdown resized the dialog — and with it the position of everything the pointer was resting on. The dialog now uses `height: min(640px, 100%)` next to the existing width, and the content region's `flex: 1 1 auto` + `overflow-y: auto` (which was already there for long exit lists) does the scrolling instead. `100%` rather than a viewport calc keeps it inside the root's padding on a short window, per the Modal contract. The cost is whitespace under the shorter pane; the alternative — measuring both panes and locking the box to the taller one — would only stabilise after both tabs had been visited once.
- **The 删除 row action was renamed 轮换 and both row actions became icons** (live request 2026-10-14). Nothing was ever deleted: the action hands the row to the candidate list, which promotes a reserve into its slot (the pool keeps its size) or — with the reserve exhausted — keeps the exit and moves it to the end. The bridge action is `rotate` (was `remove`), its envelope reports `{ rotated, promoted, remaining }` (was `{ removed, replaced, remaining }`), and every user-visible string follows: 「已轮换：候补已补位」/「已轮换：暂无候补，已移到列表末尾」/「轮换进行中，请稍后重试」. The 固定 and 轮换 buttons are now **inline SVG icons** (a closed/open padlock and a circular arrow) instead of text: the client half carries no icon dependency and emoji render in colour, which would clash with the table's monochrome ink, so the three glyphs are hand-drawn paths that inherit `currentColor` and pick up the button's hover/disabled colours. The words moved into the tooltip and the `aria-label`, and each icon's tooltip states what the click does (`statsPinHint` / `statsUnpinHint` / `statsPinLocalHint` / `statsRotateHint`) — an icon-only action has to explain itself somewhere. The settings card's rows use the same pair; the `.rowRemove` red hover (right for a 删除, wrong for a 轮换) is deliberately not reused. The two icons are a **segmented button group** rather than two buttons with a gap (live request 2026-10-14): `.actionGroup` collapses the shared edge with a `-1px` pull so the pair reads as one control with a single 1px divider and rounded outer corners only, and the hovered button lifts above its neighbour (`z-index: 1`) so its highlight is not clipped by that overlap; the settings card's 探测 text button stays outside the group, with the gap between the two things rather than inside the pair. `test/client-build.test.ts` now pins the two SVG paths, the 轮换 vocabulary, the absence of any 已删除 string in the shipped bundle, and the three group rules (collapsed edge, squared inner corners, rounded outer ones).
- **The 手填代理 and 订阅 sections no longer print their title twice** (live request 2026-10-14). Each of those two sections rendered the section heading AND the list editor's label from the same locale string, so 「手填代理（manual）」 and 「订阅（subscription）」 appeared as two identical lines in a row. `StringList`'s `label` is now optional and those two call sites pass none, leaving the heading to name the section (the layout every other section already uses); the hints, the list rows and the inputs are unchanged. The 订阅 status line keeps its prefix, which names what the numbers below it refer to.
- **The exit tables drop the 位置 column — the location rides the IP tooltip** (live request 2026-10-14). The location is reference data you look up per row, and in a table this dense the column cost more than it gave: both the exit-stats modal and the settings card's exit list lose it, and the exit IP cell now carries `title={exitLocation}`, so hovering a row's IP still answers "where is this exit?". An exit whose location is unknown (never verified) emits no tooltip rather than a dash pretending to be data. The 本机 row keeps its cell count in step so it still lines up under the header, the settings card's empty-state colSpan went 9 → 8, and three locale keys that only those columns used (`exitLocation` / `statsColLocation` / `statsLocalLocation`) are gone from both languages.
- **Pool capacity now defaults to 10, dead exits rotate automatically, and the two exit tables dropped the `#` column** (live request 2026-10-14). The onboarding capacity shipped yesterday as 20; the operator asked for 10, so `poolSize`'s schema default, the resolved-settings fallback, `ExitPool`'s constructor default, the client mirror, the bridge fallback and the docs all moved to 10 together (the profile's own value still wins, and `ipPool.poolSize` overrides it live from the settings card). A dead exit no longer just sits in the table: `ExitPool` now fires `onDead()` **once per transition to dead** (`markDeadStrike`/`markDead`; repeated strikes on an already-dead exit are silent), moves the row to the end of the pool order, and the runtime hands it to the subscription layer's `replaceExit()` — which swaps in the next-fastest reserve, or parks it at the tail when the reserve is exhausted, so the pool holds its size either way. Only subscription rows rotate (free rows belong to the refill loop's strike-eviction, manual/pinned rows are explicit user config), and replacements are serialized: each one rebuilds the sing-box config, so a burst of dead exits must not stack rebuilds — the periodic probe picks up whatever a skipped one missed. The `#` slot column added yesterday is gone from both tables (the row hover stays); the ordering it named is still the pool's own order, which is what the dead-sink and demotion behaviour uses.
- **`tok/s` no longer wraps away from its number** (live 2026-10-14). In the exit-stats modal a dense output cell rendered `704  37` and then `tok/s` on the next line, which reads as a second value rather than a unit; `.statsEndpoint` (the per-row speed note and the unverified-endpoint handle) and `.statsChip` (the summary chips, which carry `输出 704 tok/s`) are now `white-space: nowrap`.

- **The pool now carries this plugin's own lane only**: routing is scoped by path as well as by host (`proxyPathPrefixes`, default `/zen/v1`). Host-only matching meant every caller of opencode.ai rode the airport exits — measured live 2026-10-13: 77 `POST /zen/go/v1/chat/completions` in 6.3 minutes (≈12/min) from the separate `opencode-go` provider, counted as pool requests with **zero** tokens (only our adapter attributes usage) and egressing through free exits by accident, while every opencode2dsh session was quiet — which is how "I stopped using these models" and "the request count keeps climbing" were both true. `/zen/go/*` and any other path on the host now go direct and are not counted; `/` opts the whole host back in. An absent or empty list resolves to the default (never to "no path is in scope"), matching is segment-aware (`/zen/v10` is not `/zen/v1`, query strings do not defeat the match), and a caller that exposes no path stays **in** scope — guessing "out" there would silently disable routing, the failure class this layer has already been bitten by twice. `/status` reports both halves of the rule.
- The exit-stats footer entry now adapts to the space it actually gets. Its narrow form keyed off the sidebar being collapsed, but the footer row can also hold a second trigger (another plugin's) and a shared row leaves each button about half as wide — that state rendered 可用 n/m + 请求 · token inside a ~130px button (live screenshot 2026-10-13) and read as cramped. The switch follows the BUTTON's own width through a container query (`@container (max-width: 180px)`: two buttons in a ~260px row land near 130px each, one button owns ~250px, and the two-line content needs about 130px plus icon and padding): wide with the row to itself keeps both numbers, squeezed or on the 56px rail shows the token count alone with the request count in its tooltip. A browser without container-query support keeps both numbers rather than showing neither.
- The exit-stats footer entry fits the collapsed sidebar (the 56px rail, `wide: false`): it used to render the icon alone, hiding the numbers exactly when the sidebar is compact. The rail now carries the token count by itself (one number is what fits; the request count rides the tooltip), while the expanded form keeps 可用 n/m plus 请求 · token.
- `packages/plugin/lib/` is committed instead of gitignored, and the root package carries **no lifecycle script**. Measured before settling on that: pnpm runs no lifecycle script at all for a `file:` directory dependency (so `prepare` can never rescue it), the copy follows `files` with an explicit entry winning over `.gitignore`, and a git-hosted package declaring `prepare` OR `prepack` is refused outright with `ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED` — the `allowBuilds` key it prints contains the commit sha, which would cost one profile edit per commit. Custom scripts such as `build` are not blocked, so the toolchain stays reachable without triggering the gate. Because committing artifacts means someone will eventually edit `src/` without rebuilding, every build now stamps `lib/.build-manifest.json` and `test/lib-fresh.test.ts` fails when it no longer matches `src/` — a stale build cannot be merged. `pnpm build` is the single build entry: it empties `lib/` first (the inner build runs `--no-clean` so the two halves can share the directory), then the node half, then the browser half, then the manifest.
- `packages/plugin` is no longer an installable unit: its `dsh.bundle` declaration and `cordis.patch.yml` are gone, so the duplicate-row-id failure mode is unreachable rather than merely discouraged. Packing a tarball moved to the repository root (`pnpm build && pnpm pack`).

### Fixed

- **The pool can no longer sit one row above its capacity: a probe verdict must not resurrect an exit that left the table** (measured live 2026-10-14). The running profile reported `total: 11` against `poolSize: 10`, with the extra row demoted, `unknown` and **listenerless** — a row `pick()` would still hand out as the last resort, to an exit with no local SOCKS listener behind it. The mechanism is a stale write-back: a probe holds the `entry` snapshot taken before it ran, and the exit can leave the table while it is in flight (a dead rotation, a refusal replacement, an operator's 轮换), so `pool.add({ ...entry, ...verdict.node })` — an **upsert** — put the removed row back, and the same verdict's `replaceExit()` then parked it at the tail. `ExitPool.refresh()` replaces that write-back: it updates only the admission-measured fields (protocol, exit IP, location, latency, grade) on a row that is still in the table, mutates it **in place** so the pool order is untouched, and returns false — dropping the verdict — when the row is gone. The same round closed the mirror-image hole in `Onboarder.replace()`: two callers can ask for the same exit's replacement (the dead rotation and the probe already in flight), and the second one computed `selected − (a slot that is no longer there) + next`, which is one slot **bigger** than the selection — one extra local listener. A replacement whose address is in neither the table nor the selection is now a no-op, while a not-yet-admitted onboarding candidate (which is in the selection, since the smokes run before anything reaches the table) is still replaced normally. Covered by two `refresh()` tests (facts land in place, a removed row is not written back, identity/source/pin are never rewritten) and two onboarder tests (the late duplicate promotes nothing and requests no rebuild; a real replacement still swaps its reserve) — verified load-bearing by disabling the guard and watching the duplicate test fail.
- **Lowering `poolSize` now converges the live pool instead of only the next onboarding** (live 2026-10-14). The operator set the capacity to 10 from the settings card while 16 exits were online, and nothing moved: `poolSize` bounded future admissions only, so the pool kept serving 16 and kept all 16 ports open — a capacity setting that lies about the pool's size. `Onboarder.trim()` now drops the worst unpinned exits down to the capacity (the same grade → latency → oldest ordering `evictWorst()` uses, which is the onboarding's own "keep the fastest" ranking) and rebuilds the config with only the survivors, so their listeners close with them. The runtime calls it at the end of every live reconfig when the pool is over capacity, serialized with the other rebuilds; it is a no-op for a pool at or under capacity and for a pool this onboarder does not own. `ExitPool.evictWorst()` now returns the evicted id (null when nothing can be evicted) because the caller has to close that exit's listener too.
- **A leftover column-width rule was silently squeezing the stats table's IP column** (live 2026-10-14). When the `#` slot column was removed earlier the same day, the modal's `th:nth-child(N)` width block stayed at its ten-column shape, so a nine-column table applied ten rules: the IP column rendered at 4% and the last rule applied to nothing. With the location column gone the table is eight columns and the block is rewritten to match (IP 25% — it now owns the tooltip target and the unverified-endpoint handle — state 12%, requests 8%, input 8%, output 11% because it carries the `N tok/s` note, cache 8%, latency 9%, last-used 19%). The comment records why this block has to stay in step with the header: a leftover rule fails silently by squeezing the first column, which is exactly how it went unnoticed.
- **A promotion no longer leaves an orphaned local listener** (live 2026-10-14). `Onboarder.#promoteAfterRefusal()` handed the rebuild `selected + next` BEFORE swapping the refused slot out of the selection, so the config kept an inbound for an exit the pool had already dropped: measured live, 16 pool exits against **21** sing-box listeners — five ports listening for nobody. The rebuild now receives the next selection (`selected − refused + promoted`), and only commits it once the rebuild succeeds. Covered by an assertion that every `select()` call is a subset of the live pool.
- **Bounded pool onboarding: a new `poolSize` setting (default 20) speed-tests every candidate, keeps the fastest N and shrinks the local listeners to them** (live request 2026-10-13). The operator's ask was two-sided — "池子默认 20 个" and "避免建立太多本地连接" — and both halves needed the same pipeline, because the number of exits the pool keeps IS the number of local SOCKS listeners the conversion opens (a 44-node airport used to mean 44 of them). `Onboarder` (`src/pool/onboard.ts`) runs the round: **speed pass** (the documented coarse screen — latency + exit IP + geo — through each candidate's own port, on the shared prober so a paid airport is never hammered), **select** the fastest `poolSize` in latency order, **shrink** by re-running the conversion with only those slots, then the **OpenCode connectivity test** (models list + 1-token smoke) fastest-first. The speed pass is not optional decoration: this airport fronts many distinct nodes on ONE edge `host:port` and separates them by TLS SNI, so a bare TCP handshake measures every candidate identically — only an in-tunnel request can rank them. Ports became **slot-stable** (a node's port follows its position in the candidate list, not its position in the emitted subset), which is what lets a rebuild shrink to 20 or add a reserve back without repointing any survivor: the pool's exit ids, their health, their passive counters and their session stickiness all survive. A candidate the upstream refuses (a failed smoke, or a 401/403 — **429 is explicitly NOT a refusal**: it is a spent quota, so that exit is admitted and cooled) is **replaced by the next-fastest reserve**; when the reserve is exhausted the refused exit is **kept but demoted to the tail** — `ExitPool.demoteToTail()` re-inserts it at the end of the pool's own order, `pick()` ranks demoted exits last so they still serve when nothing else is usable, `markOk()` clears the demotion when a later probe verifies the exit, and the exit table shows 已降级. The same replacement runs when a pool member is refused *after* onboarding (a periodic probe verdict routes back through `SubscriptionFetcher.replaceExit()`). Capacity is enforced across every source: `ExitPool.poolSize` bounds `admissionQuota()` for the free refill, the onboarding evicts the worst unpinned row (`evictWorst()`) when it needs a slot, and pinned/manual rows are explicit user config that is never evicted. If the speed pass measures **nothing at all** (a blocked echo endpoint, a transient outage) the candidates are kept unranked in subscription order and the pool holds its capacity instead of draining to zero — a measurement failure must not read as "44 dead nodes". Verified against the real subscription body through the rebuilt pipeline: 44 candidates → 44 screened → 20 admitted → shrink called with 20 slots → **20 local listeners** (24 reserves). Covered by `test/onboard.test.ts` (7 tests: ranking+cap+shrink, reserve promotion, tail demotion, 429-is-not-a-refusal, `replace()` both ways, and the nothing-measured fallback) plus pool-level tests for `poolSize`/`admissionQuota`/`evictWorst`/`demoteToTail`/`pick()` ordering, `generateConfig` slot stability, and the settings/bridge projection.
- **Both exit tables got a fixed `#` slot column and row hover**: the first column names the exit's position in the pool's own order (the onboarding's speed rank, `#1` = fastest) and is stamped before the stats modal's display sort, so sorting by requests or latency does not renumber it; the hovered row is tinted across all nine-or-ten numeric columns. Requested alongside the pool cap (live 2026-10-13).
- The repository installs from Git: `dsh plugin --profile web add github:xbzbing/opencode2dsh`, or `... add file:<checkout>` for a local clone. No publish step, no build step, and no `allowBuilds` entry. The root package was a private shell whose only dependency was `"@opencode2dsh/dsh-plugin": "^0.3.1"`, so pnpm resolved the upstream package from the registry — and the loader imports the patch ROW's `name`, not the bundle, so it loaded that registry copy while the local build sat unused; a fresh clone was worse, because `lib/` is gitignored and neither install path builds anything. The root is now the installable unit: it carries the plugin's `main` / `exports` / `dsh.client` plus its four runtime dependencies (no nested `file:`, which a git-hosted package cannot resolve — pnpm looks for it relative to the INSTALLING project), and it is named `@opencode2dsh/dsh-plugin` so the existing row already points at it. That name is what makes the three dangerous paths safe: an install now REPLACES an npm-sourced dependency instead of adding a sibling bundle (a sibling would insert `id: opencode2dsh` twice and break settings saves), and the loader's import resolves to this package rather than a second copy. Verified end-to-end in a throwaway profile: exactly one `id: opencode2dsh` row, no skipped bundles, and the installed module imports with `apply` / `Config` / the client export all present.
- Per-exit traffic statistics: the plugin now knows **which exit carried each request**, how many requests each exit served, and how many tokens went through it. The accounting rides two existing seams instead of a new pipe: the routing dispatcher stamps its `pick()` decision into the adapter's ALS routing context (`exitId`, or a `direct` marker when pool-host traffic falls back), and the adapter — the one layer that reads the response's `usage` — records each usage chunk against that stamp as the stream passes through (`attributeUsage()` wraps every attempt's output, so a rotate restart attributes each attempt to the exit that actually carried it). The pool additionally tracks last-used stamps and in-flight counts per exit plus a direct-fallback counter; all of it surfaces on `/status` as `requests` / `lastUsedAt` / `inFlight` / `tokens` per exit and a `direct` bucket. Counters are process-lifetime (restart resets them, by design). Covered by `test/exit-stats.test.ts` (8 tests: activity bookkeeping, context stamping, request lifecycle incl. the silence sentinel, token accumulation, pass-through identity, and an adapter end-to-end run), a bridge projection test, and a bundle check that the tracker singleton is defined exactly once across chunks.
- The exit-stats modal now has a **本机 row** — model traffic that left from this machine instead of a pool exit. Two local buckets feed it: `direct` (pool-host traffic that should have used an exit but could not) and the new `local` (hosts outside `proxyHosts`, plus every request while routing is off), merged into one row with requests, tokens and its own last-used stamp. The adapter is the accounting point, because it is the only layer that sees every model call: `attributeUsage()` now records an unstamped response against `LOCAL_EXIT_ID` instead of dropping it, so the row stays truthful whether the pool is off, misconfigured or healthy — and a pool that silently routes everything locally can no longer look healthy behind a modal full of zeros (the exact failure below).   插件现在把会话标识确定性映射成官方格式（同一对话仍映射到同一会话，会话
  亲和不受影响），并在发往上游的请求体缺失这两个工具时注入最小桩工具（纯
  聊天附带 `tool_choice: "none"`，模型不会真的调用它们）；免费源准入冒烟
  探测同步改为流式并携带桩工具。

## 0.3.1 (2026-09-11)

### Fixed

- **旧版 DSH 上插件加载失败的问题（用户反馈 `list slot "settings.plugin.item" requires options.id`）。**
  `settings.plugin.item` 槽位在 DSH 0.1.0-rc.7 起由 list（按 `id` 注册）改为 keyed
  （按 `key` 注册）；0.3.0 的设置页卡片按新版 keyed 形态注册，在旧版 DSH
  （≤ 0.1.0-rc.6）上会让整个插件加载失败、启动页报错。现在卡片注册前会探测宿主
  声明的槽位类型，按对应形态注册，两边都能用；即便宿主行为异常，注册失败也只
  跳过设置卡片（控制台警告提示升级 DSH），模型路由不再被拖垮。

## 0.3.0 (2026-09-09)

The release where the IP pool actually works.

### Fixed

- **模型流量现在真正经过 IP 池。** 此前 Node 内置 fetch 与插件所用 undici
  是两个隔离实例，池开启后模型请求仍然直连、路由从未生效。现在开启
  IP 池后模型流量会真实走池中出口。
- **卡死回合不会再挂住整个会话。** 请求遇到出口无响应时会在超时后
  自动换出口重试或如实报错，不再无限等待。
- **慢响应的正常请求不再被误判为坏出口。** 响应哨兵改为双窗口：
  连接阶段 2 秒严格判定死出口，隧道建立后等待响应头放宽到 10 秒，
  避免误杀慢首包的健康流。
- **上游 5xx 不再连带惩罚出口。** 模型自身报错（如权限不足的模型对
  所有人返回 500）不会再把出口标记为失效导致全部流量静默直连。
- **免费源准入恢复正常。** 上游现在要求会话伪装头，探测请求已同步
  补齐；此前免费源候选全部被误拒。
- **池首次攒到出口后自动启用路由**，无需再手动改一次设置来触发。

### Added

- **免费代理源从 26 个扩展到 48 个**，全部逐个实测可用后接入，每轮
  候选量约提升 75%。
